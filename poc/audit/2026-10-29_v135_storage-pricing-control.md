## 2. 唯一被扫的变量

```
budget -= RENT_UNIT * rung * (len(ops) + kw)      # 每个付费步 t >= BASE_GRACE，叠加在 DECAY=1.0 与 ACT_COST 之上
RENT_UNIT = ACT_COST / MAX_OPS = 0.3 / 40 = 0.0075   # 由两个冻结常数导出，从未搜索
rung: FREE=0（== v133 原样）, P1=1, P2=2
```

先验理由（写在预注册里、在看到结果之前）：满库 40 个 op 存一步 = 一次动作的价格；窗口按持有的槽位数 `kw` 收，
所以**产生 v133 胜利的那台仪器本身被计价了，没有被豁免**。

冻结项一个没动：DECAY / GAIN / ACT_COST / B0 / BUDGET_MAX / CONC_\* / MAX_OPS / N_BASE_OPS / VAR_P /
SENSE_P / ACUTE_PUNISH / COMBINE_P / K_PRED / W_MAX_CAP / DORM_N / CLEAR_N / FORGET_AFTER / BASE_GRACE /
`couples()`。保留档固定在 R0 CLEAR（v132 已四次证伪 RETAIN/SUPPRESS）。

## 5. 一个必须自己先说的方法学坑：ER_paid 那一列在收租后是**过时的**

探针里 `er(q,g) = -1.0 + q*(3g - 0.3)` 把 DECAY=1.0 与 ACT_COST=0.3 写死了，**不含存储租金**；
表头那句 `vs433`（gamma 是否 ≥ 0.4333）也是**免租时代**的盈亏平衡点。所以一个收租臂打印 "OVER"
**并不等于**它自养。我另写了 `v135_priced_breakeven.py` 把租金加回去：

```
income/step = GAIN * q * g                      (GAIN=3.0，一次成功动作进账 3.0)
cost/step   = DECAY + ACT_COST*q + RENT_UNIT*rung*units
gamma*      = cost / (GAIN*q)                   (定价后的盈亏平衡 gamma)
```

主判据臂：cost 1.6046、income 2.5143、**ER_priced = +0.9096**、gamma\* = 0.5576 < gamma 0.874 ⇒ 自养。

**但是这里有个更重要的、方向相反的诚实发现**：

> **21 个臂里没有一个 ER_priced < 0**——包括所有存活 0.000 的臂。
> INST×P2@0.02 平均净收入仍是 **+0.067/步**，而它 40/40 全死。

这与 v128 的结论完全一致，并且第三次独立复现了它：
**平均收支不是死因，雪崩才是。** 收租只是缩短跑道，让本来就要来的雪崩来得更早
（INST 中位寿命 1334 → 1066 → 876）。因此"定价后 ER > 0"是**必要非充分**条件，
不能单独拿它当"自养"的证据——必须和存活率一起读。本审计的判定用的是预注册写死的
存活 + gamma 双条件，没有用 ER 单独下结论。

一个附带的、必须标注的偏倚：收租臂的 gamma_paid 略微**上升**（PERS K5：0.869 → 0.874 → 0.876），
这不是"租金让 agent 变准了"，而是**幸存者偏倚**——只有更好的 run 活得久，付费步平均被拉高。
同理 `span_end` 在 P1/P2 下几乎不变（6.0 / 6.0 / 6.4）也是混合量：它是"死亡快照"与"活到终点快照"的平均，
存活率一变，这个混合比就变，**不可跨租金档直接比较**。

仪器 I1/I2/I3 读真值，只用于审计；I4（held_units）/I5（rent_paid）是纯记账。四类都不进决策。

## 7. 机制：租金到底做了什么（一阶实测，不是推测）

三条实测事实，按证据强度排：

1. **租金是"余量探针"，不是"机制杀手"。** 同一笔 P1 租金（≈0.3/步）：
   对 PERS K5（免租余量 +1.205/步）只削掉 26% 的存活（0.500 → 0.425）；
   对 INST（免租余量 +0.776/步）把仅存的 0.025 存活**削到 0**。
   效果与免租余量成反比 ⇒ 定价没有引入新的墙，它只是把 v133 已经量出来的
   "入口质量差距"（I1 = 0.59 vs I2 = 0.08，7×）翻译成了预算语言。

2. **租金不改变库的形态，只改变跑道长度。** PERS K5 @0.01 的 |L| 曲线：
   FREE `35 27 24 22 22 21 20 20`，P1 `35 27 24 22 21 20 18 17`，P2 `35 25 23 20 18 16 14 13`；
   span 曲线 FREE `6.9→4.0`，P1 `6.9→3.4`，P2 `6.9→2.5`。
   **三条曲线都平坦化**（对比 INST 的 `30 24 16 12 8 5 2 0`、span `6.2→0.1` 单调崩塌），
   即 v133 的侵蚀止住这一结论在收租后仍然成立，只是终值略低。
   租金没有触发 v132 那种"容量坟场"式退化——因为 R0 CLEAR 仍在删，休眠体不堆积。

3. **覆盖率/选择率分解几乎不动。** PERS K5 @0.01 的 covF/selF：FREE 0.85/0.15、P1 0.85/0.15、P2 0.85/0.15。
   INST 的 0.53/0.47 在三档下也是 0.53/0.47 → 0.52/0.48。
   ⇒ v133 的"残留瓶颈是覆盖率（但已不致命）"这一条在定价后不变；租金没有把瓶颈搬回选择侧。

## 8. 局限（六条，按严重度）

1. **RENT_UNIT 只有一个先验值，没有做量纲扫描。** 我拒绝搜索它（K-NO-TUNE-TO-WIN），
   代价是：P2 已经到 DECAY 的 64%，若真实代谢成本更高，结论可能翻转。
   已知的定量边界（从已测数字算出，不是新跑的实验，标注为推论）：PERS K5 @0.01 的免租净收入是
   **+1.205/步**，而每档租金实收 **0.317/步**（= 0.0075 × 42.2 个持有单元），
   所以要把**平均**收支打到 0 需要 **rung ≈ 3.8（≈1.20/步，约 DECAY 的 120%）**。
   但按第 5 节，平均收支为 0 也未必是死因（雪崩才是），因此这个边界只说明"定价没有逼近临界"，
   不能说明"再贵一点也安全"。
2. **ORACLE 天花板保持在 FREE。** 按预注册这样做是为了与 v130/v132/v133 记录的天花板可比，
   但严格说"诚实臂收租 vs 天花板免租"对诚实臂不利 ⇒ 0.425 vs 0.075 这个 5.7× 是**保守**方向。
   若也给 ORACLE 收租，它只会更低。
3. **入口位点不完整（登记为 v136，没有偷偷折进本实验）。** 只有"确认/组合成员判定"读 P；
   **触发（trigger）与铸造（minting）仍读原始噪声 sensed**。所以 v133/v135 量到的是
   "把去噪用在刀刃上"的收益，不是"全面去噪"的收益，后者可能更高也可能因滞后更差。
4. **`span_end`、`gamma_paid` 在跨租金档比较时含幸存者偏倚**（第 5 节），已在正文标注，
   判定没有依赖它们。
5. **只测了 SMALL(8 通道) / W=4 / 单一 K=5 / 单一 CONF=PERS。** BOTH 入口与 K∈{3,9} 的定价响应
   没有跑（属 v133 剂量-响应材料），所以"更长窗口更贵也更准"的净收益曲线在 OPEN(64) 世界仍未知。
6. **租金按"持有量"线性收，不按"内容价值"收。** 这与生物维持成本的直觉一致（K-BIOLOGY-NOT-PROOF：
   只是设计期提示），但正面依据是 v124/v125 的实测教训 + 冻结常数导出单位，不是大脑。

## 9. 账本更新（第一档：实测）

**保留**（v133 条目 (9)）：确认入口是墙的一部分——**现在带着定价对照的支撑，不加限定词**。
支撑数字：同一笔 P1 存储租金下，PERS K5 存活 0.425 / gamma 0.874 / 定价后 +0.910 每步，
INST 存活 0.000；drift 0.02 下 0.250 vs 0.000，而 ORACLE 在 0.02 为 0.000。

**新增 (10)**：**平均收支不是死因，雪崩是——第三次独立复现。**
v128（漂移雪崩）、v132（保留×组合）、v135（定价后 21/21 臂 ER_priced > 0，含全部存活 0 的臂）。
推论（第二档）：任何"把平均账做平"的干预都不足以救活；能救活的干预必须改变**尾部**
（要么让余量厚到雪崩打不穿，要么让库形态在雪崩后仍可再生）。v133 的 PERS 属于前者：
它把余量从 +0.776 抬到 +1.205（免租），并把侵蚀曲线平坦化。

**新增 (11)**：**存储定价是可负担的**，在 RENT_UNIT = ACT_COST/MAX_OPS 这个由冻结常数导出的单位下，
去噪窗口（K=5，5 个槽位）的租金 = 0.0375/步 = DECAY 的 **3.8%**，库部分（实测平均 37.2 个 op）
= 0.279/步 = **27.9%**，P1 合计实测 0.317/步 ≈ **32%**；
两者都没有把静态解（drift 0）打下去（存活 1.000，含 P2 的 64%）。
⇒ **"结构要付维持费"这条约束本身不是 TUF-E 的墙**；墙仍在覆盖率一侧（covF 0.85）。
附带一个量化对比：**去噪仪器本身只占这笔账单的 12%**（0.0375 / 0.317），
即 v133 的胜利不是靠"偷偷养了一台昂贵仪器"买来的——贵的部分是库，而库在 v131 之前就一直在那儿。

**订正**：无。v133 的结论没有被削弱，也没有被夸大——本实验原本是为"撤回条目 (9)"准备的
（预注册里 H-PRICED-KILLED 分支写好了撤回措辞），结果没有触发。撤回草稿按 flag-don't-delete 留在
预注册文件里，不删。

## 10. 对跨线（Hy / tufe-cardinal）的后果

1. **我对 Theorem C 应用方式的批评 (1) 得到第二次一阶支撑。**
   DPI 的 N-free 上界只对 `Y → B → A^N`（重采样自己的信念）成立；对 `Y → A^N`（对世界的独立观测）不成立。
   v133 给出去噪实测（I1 0.59 → I2 0.08），v135 现在证明**这个去噪在付出真实代谢代价后仍然净值**
   （+0.910/步，存活 0.425）。也就是说：这不是"用免费内存换来的表观信息增益"，
   而是"用 8% 的 DECAY 买到 7× 的入口误差下降，且这笔交易在预算里是正的"。
   建议给 Hy 的交换件（只交换不变量，按双基底协议第 1 条）：
   **在 N 次独立观测下，为维持窗口所需的最小代谢率与 I(Y;A^N) 增益之间的收支不等式**——
   这是一个两条线都能独立推导的量，且我们这边已经有实测数字可以对照。
2. **同源坦白仍然有效**：两条线同一巩固者，Hy 那边若推出同一个不等式，**不算双重确认**（协议第 2 条）。
3. Theorem F（行为不可区分时分离功发散）在这批数据里有个有趣的对应：INST 与 PERS 在
   **平均**收支上不可区分（都是正的），但在**存活**上相差 ∞（0.000 vs 0.425）——
   即"平均量"这个描述层面本身对这两个机制是不可区分的，而它们的命运完全不同。
   这是第 5 节结论的另一面，值得作为跨线议题提出。
